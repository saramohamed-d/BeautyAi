# BeautyAI

AI-powered multi-agent platform connecting patients with verified aesthetic
and dermatology doctors and clinics in Egypt and the Arab world.

> **Status: Sprint 0 — Project Foundation.**
> Only infrastructure exists at this stage: Docker Compose, FastAPI skeleton,
> Next.js skeleton, database wiring, health checks, logging, and tests.
> No agents, RAG, matching, or booking logic exist yet — see
> `docs/architecture.md` for the full roadmap.

## Stack

- **Backend:** Python 3.12, FastAPI, SQLAlchemy (async), Alembic, PostgreSQL (pgvector), Redis
- **AI (future sprints):** OpenAI API, LangGraph, LangChain
- **Frontend:** Next.js 14 (App Router), TypeScript, Tailwind CSS, TanStack Query
- **Infra:** Docker Compose

## Prerequisites

- Docker + Docker Compose
- (Optional, for running services outside Docker) Python 3.12+ and Node 20+

## Setup

1. Copy the environment template:

   ```bash
   cp .env.example .env
   ```

2. Start everything:

   ```bash
   cd infra
   docker compose up --build
   ```

   This starts, in order (via healthchecks/`depends_on`):
   - `postgres` (pgvector image — pgvector isn't used until Sprint 8, but
     using the pgvector-enabled image now avoids re-provisioning the
     database later)
   - `redis`
   - `backend` (FastAPI, hot-reload, on port `8000`)
   - `frontend` (Next.js dev server, hot-reload, on port `3000`)

3. Visit:
   - Frontend: http://localhost:3000
   - Backend root: http://localhost:8000
   - Backend health check: http://localhost:8000/api/v1/health
   - Interactive API docs (auto-generated by FastAPI): http://localhost:8000/docs

The landing page at `localhost:3000` calls the live backend health endpoint,
so a green status there proves the full stack — Next.js → FastAPI → Postgres
+ Redis — is wired together correctly.

## Running the backend without Docker (optional)

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

You'll need Postgres and Redis reachable at the URLs in your `.env`
(e.g. run `docker compose up postgres redis` from `infra/` and leave the
rest running locally).

## Running the frontend without Docker (optional)

```bash
cd frontend
npm install
npm run dev
```

## Database migrations (Alembic)

No models exist yet (Sprint 1). Once they do:

```bash
cd backend
alembic revision --autogenerate -m "add patients table"
alembic upgrade head
```

## Running tests

Tests are integration tests that hit the real `/health` endpoint, which
pings Postgres and Redis — so the database and cache need to be running:

```bash
cd infra
docker compose up -d postgres redis

cd ../backend
python -m venv .venv && source .venv/bin/activate   # if not already active
pip install -r requirements.txt
pytest -v
```

Expected output: 3 passing tests (`test_health.py`).
